DBA-Bench 则把 agent 放进更接近生产的 PostgreSQL 运维场景。结果非常冷静：自动 DBA 的 safe pass score 远低于专家人类 DBA。它说明让 agent 管数据库不是“会写 SQL”就够了。真实数据库涉及锁、事务、索引、迁移、权限、备份、回滚和业务 SLA。短期更合理的产品形态，不是让 agent 自动改库，而是只读诊断、生成变更计划、列出风险、准备回滚脚本，然后由人审批执行。

今天的重点技术解读，我想讲 FlowEvo。大多数 agent demo 的隐性成本，是每次任务都从零规划。模型读上下文、想步骤、调工具、失败后再修正。FlowEvo 的思路是，把成功和失败轨迹抽象成可执行 workflow，再编译成 skill bank。下一次遇到相似任务时，agent 不必重新思考所有步骤，而是调用已有技能并做局部调整。它的价值不只是提高成功率，而是把 agent 的经验变成可复用、可测试、可审计的资产。未来企业 agent 很可能不只是一个聊天框，而是一个技能仓库、权限系统、执行运行时和审计系统。
