今天值得重点讲的一篇技术论文，是 FineVerify。它研究的是 agentic search，也就是让模型像研究助理一样搜索多个来源，回答复杂问题。传统做法会让模型多跑几条轨迹，然后选择看起来最好的答案。但复杂问题里正确答案很稀疏，模型自己的打分也不总是可靠。FineVerify 的方法是把一个大问题拆成多个可检查的小问题，对每个候选答案逐项验证，最后聚合这些局部检查结果。它的价值在于，把“这个答案总体对不对”变成“这些具体事实有没有被证据支持”。对 RAG、deep research、金融检索、法律检索和政策分析来说，这种 verification trace 可能会变成未来企业 agent 的标准输出。

和 FineVerify 相互呼应的是 Harness-1。它的核心观点是：不要让模型用上下文去记账。搜索 agent 经常需要维护候选文档、证据链接、已验证事实、未完成约束和上下文预算。如果这些都放进 prompt，模型就会浪费大量能力做本该由系统完成的状态管理。Harness-1 把这些状态外置到环境侧，让模型专注于语义决策：搜索什么、保留什么、验证什么、什么时候停止。这个思路对工程实现非常重要。一个好的 agent 系统，不是把所有东西塞进长上下文，而是把状态、证据和验证记录设计成可恢复、可压缩、可审计的数据结构。
