第二条信号是 SAFARI。真实 agent 一旦跑长任务，日志会非常长，工具调用、检索结果、中间状态、错误重试都会堆起来。过去很多失败分析方法是把整条 trajectory 塞进大模型上下文，让它判断哪里错了。但长程任务很快会超过上下文窗口，也会出现注意力稀释。SAFARI 的思路是把故障归因变成主动调查：模型不再线性阅读全部日志，而是用工具检索和读取轨迹片段，再用短期记忆跨轮推理。论文报告，在两个故障归因数据集上，它比已有方法高出约 19% 到 20%。对工程团队来说，这非常实用。未来企业 agent 不只需要最终成功率，还需要像分布式系统一样的 trace、root cause、证据片段和诊断 UI。

第四条信号是 coding agent 的成本控制。今天有一篇论文叫 Bayesian control for coding agents。它把编码 agent 的工具编排建模为成本敏感的序贯假设检验。简单说，agent 生成一段代码后，可以先跑便宜的 lint，也可以跑单测，也可以跑昂贵的集成测试或 verifier，还可以让模型修正。问题是每一步都有成本，而且测试也不总可靠。贝叶斯控制器会维护一个信念：当前候选代码到底有多可能是正确的。然后它再决定是否继续取证、修正、验证或停止。这个思路很重要，因为未来 AI 编程工具不只是写代码，还要学会管理验证预算。对工程团队来说，真正有价值的是减少错误合入，同时不把 CI 成本烧穿。

第五条信号是长上下文推理的 KV cache 压缩。CompressKV 关注一个被很多产品宣传掩盖的问题：模型支持 100K 或 1M token 并不意味着成本可以忽略。生成每个新 token 时，模型都要访问过去上下文的 key-value cache。上下文越长，显存和带宽压力越大。CompressKV 的思路是识别一些更像语义检索器的 attention heads，用这些 head 来判断哪些 token 的 KV 值应该保留，再按层分配缓存预算。论文报告，在 LongBench 问答任务中，只保留 3% 的 KV cache 仍能保留 97% 以上 full-cache 性能。不过 arXiv 页面提示这篇文章和一篇旧文有大量文本重叠，所以需要核对版本和代码。即便如此，这个方向本身很关键：长上下文产品的竞争，会越来越依赖 cache compression、RAG reranking、chunk routing 和动态预算。
